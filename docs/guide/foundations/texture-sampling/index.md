# Текстуры и sampling: UV и фильтр

::: info Только native
Продолжаем [прошлую страницу](../texture-load/); клавиши `F` и `A` переключают фильтр и адресацию.
:::

`textureLoad` брал целые тексели — но интерполированный UV дробный.
Что читает текстура в точке `(0.5, 0.5)`, лежащей между четырьмя центрами?

**Эксперимент:** та же текстура 2×2, но цвет фрагмента вычисляет **сэмплер**.
По умолчанию — билинейная фильтрация с зажиманием к краям; `F` переключает nearest/linear, `A` — clamp/repeat.

## Сэмплер

Сэмплер — отдельный ресурс с политикой чтения, пригодный для любой текстуры:

```rust
gpu.device.create_sampler(&SamplerDescriptor {
    label: Some(&format!("Quad sampler ({filter}, {address})")),
    address_mode_u: address_mode(address),
    address_mode_v: address_mode(address),
    address_mode_w: address_mode(address),
    mag_filter: filter_mode(filter),
    min_filter: filter_mode(filter),
    mipmap_filter: wgpu::MipmapFilterMode::Nearest,
    ..SamplerDescriptor::default()
})
```

- **address mode** — что происходит с адресами текселей за краями текстуры (механика — ниже): `ClampToEdge` продлевает крайний тексель, `Repeat` заворачивает по модулю.
- **mag/min filter** — фильтрация при увеличении и уменьшении; здесь намеренно одинаковая.
- `mipmap_filter` пока без роли: у текстуры один уровень, mip-ы появятся в [следующей главе](../mipmap-minification/).

В bind group теперь два участника: параметры не нужны, но текстура и сэмплер идут парой.

## textureSample и веса

```wgsl
@group(0) @binding(0) var TEX: texture_2d<f32>;
@group(0) @binding(1) var SAMPLER: sampler;

@fragment
fn fs_main(input: VertexOutput) -> @location(0) vec4<f32> {
    return textureSample(TEX, SAMPLER, input.uv);
}
```

При `Nearest` сэмплер выбирает тексель, чей центр ближе к UV, — кадр совпадает с [textureLoad](../texture-load/) байт в байт (это и проверяет тест).

При `Linear` значение смешивается из четырёх соседних текселей — **билинейная фильтрация**.
Веса — те же веса отрезка из [«Интерполяции»](../vertex-colors/), применённые по каждой оси: дробная часть UV внутри текселя задаёт пару коэффициентов `(s, 1-s)` и `(t, 1-t)`, и вклад каждого текселя равен произведению своих коэффициентов.
В точке `(0.5, 0.5)` — ровно посередине между центрами `(0.25, 0.25)` и `(0.75, 0.75)` — все четыре веса равны `0.25`.

Смешиваются **линейные** значения: sRGB-текстура декодирует тексели до фильтрации.
Это то же правило «операции в linear» из [главы о цвете](../srgb-mixing/), применённое железом: если бы фильтр усреднял коды, серый центр (188) превратился бы в грязный тёмный (128).

Контрольная точка: в центре кадра четыре цвета — красный, зелёный, синий и белый — смешиваются равными весами.
Каждый канал есть сумма двух единиц из четырёх: линейное среднее `(0.5, 0.5, 0.5)` → код 188.

## Режимы и границы

При `Clamp` адрес текселя за краем прижимается к краевому текселю; при `Repeat` — заворачивается: адрес по модулю ширины.
Куда применяется режим? Не к самому UV, а к **адресу каждого текселя, который затребовала фильтрация**.
Билинейная выборка при UV `(0.1, 0.1)` читает тексели с индексами `−1` и `0` по каждой оси — и именно эти четыре адреса уходят в режим границы.
Поэтому для `Linear` режимы различаются и **внутри** `[0, 1]`: в полутекселе от края часть адресов уже отрицательна.

Контрольная точка — верхний левый угол кадра (UV ≈ 0): `Clamp` даёт чистый красный (все четыре соседа прижались к текселю `(0, 0)`), `Repeat` подмешивает белый, зелёный и синий с противоположных краёв — угол «сглаживается» через шов.
`Nearest` адресует единственный тексель и в этой точке режимов не различает: разница между ними видна на UV вне `[0, 1]`, что станет нормой в главе о повторных узорах.

Автоматическая проверка:

- nearest-режим — с эталоном textureLoad, нулевой допуск;
- билинейный центр — с расчётным кодом 188;
- крайние пиксели — с аналитикой `Clamp` и `Repeat`;
- весь кадр — с собственным эталоном.

```sh
cargo run -p texture-sampling
cargo test -p verify
```

## Проверьте модель

1. Вычислите веса четырёх текселей для UV (0.375, 0.625) и предскажите линейный цвет.
2. Почему `filterable: true` появилось в layout'е этой главы, хотя текстура та же?
3. Задайте UV правой вершины (1.5, 0). Что покажет правый край при `Repeat`? при `Clamp`?
4. Чем `textureSample` отличается от `textureLoad` по аргументам и по роли сэмплера?

::: details Решения и контрольные выводы

1. s = (0.375 − 0.25)/0.5 = 0.25, t = (0.625 − 0.25)/0.5 = 0.75. Веса: красный 0.75·0.25 = 0.1875, зелёный 0.25·0.25 = 0.0625, синий 0.75·0.75 = 0.5625, белый 0.25·0.75 = 0.1875. R = 0.1875 + 0.1875 = 0.375, G = 0.0625 + 0.1875 = 0.25, B = 0.5625 + 0.1875 = 0.75. Линейный цвет ≈ (0.375, 0.25, 0.75).
2. Фильтрация — свойство пары «текстура + сэмплер»: wgpu требует, чтобы формат текстуры допускал фильтрацию, прежде чем разрешит filtering-сэмплер в bind group.
3. При включённом по умолчанию `Linear + Repeat`: заворачивание адресов даёт fract-координату 0.5 по U — ровно между центрами текселей, а по V край сидит на шве (адреса соседей уходят за 0 и заворачиваются) — в смешении участвуют все четыре цвета, и предельное значение правого края стремится к линейному среднему `(0.5, 0.5, 0.5)` → коды ≈ `(188, 188, 188)`. При `Clamp` оба соседних адреса по U прижаты к столбцу 1, по V — к строке 0: край растягивается в чистый зелёный (код `(0, 255, 0)`).
4. `textureSample` принимает сэмплер и дробный UV, возвращает отфильтрованное значение; `textureLoad` берёт целые координаты текселя и уровень, сэмплер не участвует.

:::

Фильтрация решает увеличение и мягкие переходы, но при уменьшении один пиксель накрывает много текселей — и точечная выборка начинает «звенеть».
