# Уменьшение и mipmaps

::: info Только native
Финальная глава среза: клавиши `L`, `Space`, `R` — LOD, пауза, сброс фазы.
:::

Билинейный фильтр смешивает четыре текселя — но что, если один пиксель экрана накрывает их десятки?
Точечная выборка начинает пропускать клетки узора: появляется **алиасинг** — муар, мерцание, «звон».

**Эксперимент:** шахматная доска 8×8 с чёрно-белыми клетками по одному текселю, зажатая в прежний прямоугольник с повторением `k = 144`.
Каждый пиксель накрывает около двух текселей.
Фаза узора движется первые две секунды (`phase = t/8`), затем останавливается; `L` переключает LOD clamp 0/1.

## Footprint и LOD

Площадь текстуры, накрываемая одним пикселем, называют **footprint**.
У нас: `8 текселей × 144 повторов = 1152 текселей` на квад шириной 576 пикселей кадра проверки 768×576 — те же `2 текселя на пиксель` по горизонтали; по вертикали покрытие тоже превышает тексель на пиксель.
Формула-ориентир LOD: выборка на уровне 0 читает 2 текселя там, где нужен 1, значит `LOD ≈ log2(2) = 1`.
LOD считает сэмплер по изменению UV между соседними фрагментами — интуиция производных без самих производных.

## Мип-уровни на CPU

Выделение текстуры и её содержимое — разные вещи: `mip_level_count: 4` выделяет место под уровни, но не заполняет их.
Строим цепочку сами — блоками 2×2 в **линейных** значениях:

```rust
/// Builds the whole chain: each level averages 2x2 blocks of the previous
/// one in linear light, then re-encodes; the last level is 1x1.
fn mip_chain() -> Vec<Vec<u8>> {
    let mut levels = vec![checkerboard()];
    while levels.last().unwrap().len() > 4 {
        let source = levels.last().unwrap();
        let source_side = ((source.len() / 4) as f64).sqrt() as u32;
        let target_side = source_side / 2;
        let mut target = vec![0u8; (target_side * target_side * 4) as usize];
        for y in 0..target_side {
            for x in 0..target_side {
                let mut linear_sum = 0.0;
                for (dy, dx) in [(0u32, 0u32), (0, 1), (1, 0), (1, 1)] {
                    let sx = x * 2 + dx;
                    let sy = y * 2 + dy;
                    let offset = ((sy * source_side + sx) * 4) as usize;
                    linear_sum += srgb_decode(f32::from(source[offset]) / 255.0);
                }
                let encoded = (srgb_encode(linear_sum / 4.0) * 255.0).round() as u8;
                let offset = ((y * target_side + x) * 4) as usize;
                target[offset..offset + 4].copy_from_slice(&[encoded, encoded, encoded, 255]);
            }
        }
        levels.push(target);
    }
    levels
}
```

decode → среднее → encode: усреднение в линейном свете, как в [главе о цвете](../srgb-mixing/).
Загрузка уровней идёт тем же `write_texture` с `mip_level: level` — с тем же выравниванием рядов, кроме уровня 1×1, которому шаг не нужен.

У чёрно-белой шахматки блок 2×2 всегда `(чёрный + белый)/2`: уровень 1 — уже полностью серый (код 188).
Это честное следствие: на footprint 2 клетки в принципе не различимы.

## Кламп уровней

Сэмплер умеет выбирать уровень сам, но для эксперимента зафиксируем его явно:

```rust
let describe_sampler = |lod: f32| {
    gpu.device.create_sampler(&SamplerDescriptor {
        label: Some(if lod == 0.0 {
            "LOD 0 sampler"
        } else {
            "LOD 1 sampler"
        }),
        address_mode_u: AddressMode::Repeat,
        address_mode_v: AddressMode::Repeat,
        address_mode_w: AddressMode::Repeat,
        mag_filter: FilterMode::Nearest,
        min_filter: FilterMode::Nearest,
        mipmap_filter: MipmapFilterMode::Nearest,
        lod_min_clamp: lod,
        lod_max_clamp: lod,
        ..SamplerDescriptor::default()
    })
};
```

`lod_min_clamp = lod_max_clamp = lod` принуждает уровень: 0 — сырая доска, 1 — серый префильтрованный уровень.

Шейдер добавляет только трансформацию UV из uniform-параметров:

```wgsl
struct Params {
    k: f32,
    phase: f32,
};

@group(0) @binding(0) var<uniform> params: Params;

@fragment
fn fs_main(input: VertexOutput) -> @location(0) vec4<f32> {
    let uv = input.uv * params.k + vec2<f32>(params.phase, 0.0);
    return textureSample(TEX, SAMPLER, uv);
}
```

## Что дали мипы

Предфильтрация снизила чувствительность к фазе — выборка читает уже усреднённые данные, а не бросает кости по случайному текселю.
Детали при этом не восстановлены: клетки размером в полпикселя неразличимы в принципе; вернёт ли mipmap их вид — вопрос будущего про повышающую фильтрацию.
GPU-генерация цепочек (blur-проходы, compute) появится после глав о промежуточных изображениях; CPU-вариант здесь — осознанный учебный шаг.

## Проверьте модель

1. Посчитайте texels/пиксель при `k = 576`. Какой LOD ожидается и что покажет уровень 1?
2. Уровень 2 шахматки — тоже серый. Почему тогда clamp 1 выбран экспериментом, а не 2?
3. Фаза сдвигает узор на долю текселя. Почему без мипов при фазах 0 и 1/16 кадры различаются сильнее, чем с мипами?
4. Проверьте объём цепочки уровней `8+16+4+1` текселей при RGBA8... и найдите ошибку в этом утверждении.

::: details Решения и контрольные выводы

1. `8 текселей × 576 повторов / 576 пикселей = 8` текселей на пиксель, LOD ≈ 3. Для чистой шахматки это ничего не меняет: уровень 1 — серый, и все уровни выше — тот же серый; clamp 1 по-прежнему «решает» задачу. Разница между уровнями стала бы видимой на текстуре с реальной структурой, а не на двухцветной доске.
2. Уровень 2 уже 2×2 от серого уровня 1 — тот же серый; clamp 1 — минимальный уровень, решающий задачу, и он сохраняет больше информации в общем случае.
3. Без мипов выборка падает в случайные клетки — малый сдвиг меняет цвет пикселя; с мипами читается усреднённое значение, почти не зависящее от фазы.
4. Ошибка в первом слагаемом: уровень — это `8×8 = 64` текселя, а не 8. Правильная сумма `64 + 16 + 4 + 1 = 85` текселей, то есть 340 байтов — итог верен, цепочка в вопросе — нет.

:::
