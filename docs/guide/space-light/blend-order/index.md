# Порядок, depth и cutout

::: info Только native
Снимок [«Over и представление alpha»](../blend-over/): пресет B один занимает кадр, плюс depth-буфер; клавиши `O`, `T` и прежняя `M`.
:::

Один полупрозрачный прямоугольник над фоном — арифметика.
Два — уже расписание: кто ляжет первым, тот и окажется «дальним» слоем.
На этой странице три инструмента против хаоса: порядок, depth-тест без записи и cutout.

**Эксперимент:** чёрный opaque фон на весь кадр, красный прямоугольник `x ∈ [−1.5, −0.3]` и зелёный `x ∈ [−0.9, 0.3]`, оба `alpha = 0.5`, зона контроля — их перекрытие.
Локальный depth-буфер `Depth32Float`, сравнение `Less`.
Клавиша `O` меняет порядок красный/зелёный, `T` включает cutout-режим, `M` по-прежнему переключает straight/premultiplied.

## Порядок — часть данных

`over` не коммутативен: веса `(1−as)` достаются тому, кто лежит ниже.
Контрольный пиксель (центр перекрытия, мир `(-0.6, 0)`):

```text
красный затем зелёный:  (0,0.5,0) + (0.5,0,0)·0.5 = (0.25, 0.5, 0)   коды (137, 188, 0)
зелёный затем красный:  (0.5,0,0) + (0,0.5,0)·0.5 = (0.5, 0.25, 0)   коды (188, 137, 0)
```

Отсюда правило прозрачной сцены: рисовать **от дальних к ближним**, чтобы каждый новый слой ложился поверх уже накопленного.
Прямоугольники сортируются тривиально; пересекающиеся объекты сортировку ограничивают — depth из [главы «Ориентация и видимость»](../depth-culling/) тут не поможет: он решает видимость непрозрачных, а не порядок смешивания.

## Depth: тест без записи

Depth-буфер из [главы «Ориентация и видимость»](../depth-culling/) возвращается, но в половинной роли.
Слои сцены разнесены по глубине: фон на `z = −1.5`, источники на `z = −1.0` — под ortho-объёмом `near = 0, far = 2` это NDC-глубины ровно `0.75` и `0.5`.

```rust
/// NDC depth of a world z under the fixed ortho volume.
pub fn depth(z: f32) -> f32 {
    (-z - NEAR) / (FAR - NEAR)
}
```

Opaque фон пишет глубину как обычно.
Прозрачные источники глубину **тестируют, но не пишут**: тест `0.5 < 0.75` пропускает их поверх фона, а отсутствие записи не даёт переднему прозрачному фрагменту отсечь задний — тот ещё должен успеть подмеситься.
Именно поэтому в [«Over и представление alpha»](../blend-over/) все прямоугольники лежали на одной глубине и обходились без буфера вовсе, а здесь слои разнесены: копланарные `0.5 < 0.5` не пройдут никогда.

```rust
            // Opaque and cutout pipelines write depth, transparent ones
            // only test it; every comparison stays `Less`.
            depth_stencil: Some(DepthStencilState {
                format: TextureFormat::Depth32Float,
                depth_write_enabled: Some(depth_write),
                depth_compare: Some(CompareFunction::Less),
                stencil: Default::default(),
                bias: Default::default(),
            }),
```

Все четыре pipeline собирает одна функция: opaque и cutout создаются с `depth_write = true`, straight и premultiplied — с `false`.

## Cutout: alpha как маска

Листва, решётки, штриховка: альфа тут не «наполовину видимый», а «есть пиксель / нет пикселя».
Cutout-режим превращает прямоугольник в маску: верхняя половина несёт `alpha = 0.49`, нижняя — `0.51`, и решение принимает порог:

```wgsl
// Cutout: alpha is not opacity but coverage. Below the threshold the
// fragment is dropped entirely - it writes neither color nor depth, so
// both buffers keep whatever was there before the draw.
@fragment
fn fs_cutout(input: VertexOutput) -> @location(0) vec4<f32> {
    if (input.color.a < 0.5) {
        discard;
    }
    return vec4<f32>(input.color.rgb, 1.0);
}
```

`discard` — не «прозрачный пиксель», а **отсутствие фрагмента**: отброшенный фрагмент не пишет ни цвет, ни depth.
Поэтому `0.49` сохраняет и фон, и глубину нетронутыми, а `0.51` проходит и пишет оба — как opaque.
Пороговые значения выбраны строго по обе стороны от `0.5`: держать паттерн на самом пороге — доверять точности сравнения.

Пишущий depth cutout меняет и расписание перекрытия: обе половины лежат на глубине `0.5`, `Less` отклоняет второго — зону контроля внизу удерживает **первый** нарисованный, а не последний.
Смешивание в этом pipeline выключено: прошедший порог фрагмент непрозрачен по построению.

## Снимок

Один общий индексный буфер, три вершинных: фон, пара источников с `alpha = 0.5` и четыре половины с `0.49/0.51`.

```rust
/// The cutout pattern: each source splits into an upper half with alpha
/// just below the threshold and a lower half just above it.
fn cutout_vertices() -> [Vertex; 16] {
    let quads = [
        quad(-1.5, 0.0, -0.3, 0.9, Z_SOURCES, [RED[0], RED[1], RED[2], CUT_BELOW]),
        quad(-1.5, -0.9, -0.3, 0.0, Z_SOURCES, [RED[0], RED[1], RED[2], CUT_ABOVE]),
        quad(-0.9, 0.0, 0.3, 0.9, Z_SOURCES, [GREEN[0], GREEN[1], GREEN[2], CUT_BELOW]),
        quad(-0.9, -0.9, 0.3, 0.0, Z_SOURCES, [GREEN[0], GREEN[1], GREEN[2], CUT_ABOVE]),
    ];
    let mut vertices = [Vertex { position: [0.0; 4], color: [0.0; 4] }; 16];
    for (part, chunk) in quads.iter().zip(vertices.as_chunks_mut::<4>().0.iter_mut()) {
        chunk.copy_from_slice(part);
    }
    vertices
}
```

Прозрачная ветка вывода — порядок читается прямо из `match`:

```rust
            pass.set_pipeline(sources);
            pass.set_vertex_buffer(0, self.blend_buffer.slice(..));
            match self.order {
                Order::RedFirst => {
                    pass.draw_indexed(BLEND_RED, 0, 0..1);
                    pass.draw_indexed(BLEND_GREEN, 0, 0..1);
                }
                Order::GreenFirst => {
                    pass.draw_indexed(BLEND_GREEN, 0, 0..1);
                    pass.draw_indexed(BLEND_RED, 0, 0..1);
                }
            }
```

Проверка гоняет оба представления и оба порядка: контрольный пиксель обязан переключиться между `(137, 188, 0)` и `(188, 137, 0)`; в cutout верхние половины остаются чёрным фоном `(0, 0, 0)`, нижние дают полные `(255, 0, 0)` и `(0, 255, 0)`, а перекрытие внизу удерживает первый draw обоих порядков.

![Кадры blend-order: красный первым и зелёный первым.](/results/blend-order-flip.png)

Красный первым — зелёный первым: в области перекрытия доминирует последний нарисованный. Порядок команд решает всё — depth прозрачные источники лишь тестируют, не записывая.

```sh
cargo run -p blend-order
cargo test -p blend-order
cargo test -p blend-order
```

## Проверьте модель

1. Что случилось бы с кадром, включи прозрачный pipeline запись depth?
2. Почему прямоугольники этой главы разнесены по z, хотя в [«Over и представление alpha»](../blend-over/) лежали на одной плоскости?
3. Cutout: `alpha = 0.5` ровно — пройдёт фрагмент или нет? И почему паттерн использует 0.49 и 0.51?
4. Cutout без записи depth: кто выиграет перекрытие внизу — первый или второй draw, и чем это отличается от текущего поведения?

::: details Решения и контрольные выводы

1. Первый источник записал бы `0.5`; второй на той же глубине не прошёл бы `0.5 < 0.5` — смешивания не произошло бы, остался чистый первый слой. Прозрачность требует увидеть сквозь: тест без записи.
2. Coplanar-глубины сравниваются как равные, а `Less` равные отклоняет: источники никогда не наложились бы на фон. Разнос `0.5` против `0.75` даёт тесту различать слои.
3. Условие `a < 0.5` строгое: ровно `0.5` не меньше — проходит. Но держать паттерн на самом пороге значит доверять точности сравнения; `0.49/0.51` уводят решение от границы в обе стороны.
4. Без записи depth второй draw просто перезаписал бы цвет первого (смешивание выключено) — победил бы последний, как в [главе «Ориентация и видимость»](../depth-culling/) без depth. С записью `Less` отклоняет равную глубину — побеждает первый; порядок снова влияет, но зеркально.

:::
