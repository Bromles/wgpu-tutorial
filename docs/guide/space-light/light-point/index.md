# Точечный источник и конус

::: info Только native
Снимок [главы «Материал и блик»](../blinn-phong/): плоскость и камера прежние; направленный свет заменён источником с положением, `S` и стрелки.
:::

У направленного света нет положения — только направление.
Стоит дать источнику адрес, и появляются две новые величины: **расстояние** до каждого фрагмента, а если светить нужно не во все стороны — ещё **ось** с конусом, как у прожектора.

**Эксперимент:** плоскость `z = 0`, камера `(0, 0, 3)` fov 60° — сцена [главы «Материал и блик»](../blinn-phong/).
Источник над центром `(0, 0, 2)`, сила света — безразмерный множитель `0.4`; `ambient = 0`, блик убран: изучаем только прямой свет, `albedo = 0.5`.
Клавиша `S` включает конус, стрелки двигают источник по XZ с шагом `0.25` (высота держится в `0.25…4` м — источник не садится на плоскость).

## L из положения

Направление на источник больше не константа — у каждого фрагмента `P` оно своё:

```text
to_light = light_pos − P        r = |to_light|        L = to_light / r
```

Три формулы вместо одной, и появляется деление: при `r = 0` (источник точно на фрагменте) направление не определено.
Совпадение мы исключаем конструкцией (высота источника ≥ 0.25 м), а знаменатель затухания всё равно страхуем нижней границей.

## Затухание: 1/r²

Свет от точки расходится по сфере: площадь растёт как `r²`, плотность падает как `1/r²`:

```text
attenuation = 1 / max(r², r_min²)        r_min = 0.1 м
```

`max` с полом `r_min` не даёт знаменателю приблизиться к нулю: прямо под источником вклад конечен и равен `power / r_min²`.
Контрольные числа (`N·L = 1`, `albedo = 0.5`, `power = 0.4`):

```text
r = 1 м:   0.5 · 0.4 · 1/1  = 0.2        код sRGB 124
r = 2 м:   0.5 · 0.4 · 1/4  = 0.05       код 63
```

удвоение расстояния — вчетверо меньше света.

## Конус: ось и два угла

Прожектор — точка с маской: светит не во все стороны, а в конус вокруг оси.
Сравнивать будем не углы, а их **косинусы** — `dot` из [главы «Три измерения и базис»](../basis3d/) выдаёт их бесплатно: для единичных векторов `dot(a, b) = cos угла`.

Направление от источника к фрагменту — `−L`; ось конуса `spot_dir` (у нас `(0, 0, −1)`, вниз):

```text
d = dot(−L, spot_dir)          косинус угла луча к оси
```

Два угла задают конус: внутренний `15°` — полный свет, внешний `30°` — темнота.
Между ними нужен переход; берём линейную интерполяцию по косинусам — те же веса `(1−t)` и `t`, что и в [«Интерполяции»](../../foundations/vertex-colors/), только отрезок — от `cos_outer` до `cos_inner`:

```text
t = clamp((d − cos_outer) / (cos_inner − cos_outer), 0, 1)
вклад = power · attenuation · max(N·L, 0) · t
```

Проверьте по концам: `d = cos_inner` даёт `t = 1` (внутри — полный свет), `d = cos_outer` — `t = 0` (на внешней границе — ноль), посередине между косинусами — ровно половина.
Линейность по косинусам, не по углам: величина, которую даёт `dot`, и есть косинус.

## Снимок

Один источник едет в uniform — `vec3` + скаляры, encase пакует каждое `vec3` в 16-байтовый слот со скаляром в хвосте, всего 112 байт:

```wgsl
struct Params {
    view_proj: mat4x4<f32>,
    light_pos: vec3<f32>,
    power: f32,
    spot_dir: vec3<f32>,
    spot_cos_inner: f32,
    spot_cos_outer: f32,
    spot_on: u32,
};
```

Фрагментный шейдер — вся глава в одном месте:

```wgsl
    let n = normalize(input.world_normal);
    // L points from the fragment toward the source; r is that distance in
    // metres, so the clamp keeps the denominator above R_MIN^2.
    let to_light = params.light_pos - input.world_position;
    let r = length(to_light);
    let l = to_light / r;
    let attenuation = 1.0 / max(r * r, R_MIN * R_MIN);
    var contribution = params.power * attenuation * max(dot(n, l), 0.0);
    if (params.spot_on == 1u) {
        // d is the cosine of the angle between the cone axis and the
        // direction from the source to the fragment (-L).
        let d = dot(-l, params.spot_dir);
        // Linear fade in the cosines: 0 at the outer cone, 1 at the inner.
        let t = clamp(
            (d - params.spot_cos_outer) / (params.spot_cos_inner - params.spot_cos_outer),
            0.0,
            1.0,
        );
        contribution = contribution * t;
    }
    let color = ALBEDO * (AMBIENT + contribution);
```

Проверка сверяет кадры с CPU-зеркалом формулы: точка под источником на `r = 1` и `r = 2` даёт коды `124` и `63`, косая точка на `r = 2` — `44` (теряет ещё и `N·L = 0.5`). С конусом центр не меняется (`d = 1 > cos_inner`), а край гаснет до нуля.

![Кадры light-point: точечный источник слева, с конусом справа.](/results/light-point-cone.png)

Слева чистый точечный источник с затуханием `1/r²`, справа — тот же с конусом (клавиша `S`). Ось конуса смотрит вниз: центр под источником не меняется, а край пятна гаснет до нуля — сравните обод.


## Проверьте модель

1. Источник подняли с 1 м до 2 м над центром. Во сколько раз изменился прямой вклад в центральной точке? А в точке на плоскости в 1 м сбоку от центра?
2. Зачем нужен `r_min`, если совпадение источника с поверхностью мы исключили?
3. Луч ушёл точно на границу внешнего конуса: чему равен `t` и вклад? А ровно посередине между косинусами?
4. Почему маску сравниваем по косинусам, а не переводим `d` обратно в градусы?

::: details Решения и контрольные выводы

1. В центре — вчетверо (`1/1 → 1/4`, вклад 0.2 → 0.05). В любой другой точке расстояние тоже растёт, но не обязательно вдвое: например, точка на плоскости в 1 м сбоку от центра была на `r = √2`, станет на `r = √5` — вклад упадёт в 2.5 раза, и ещё немного изменится `N·L`.
2. `r_min` — пол знаменателя: он ограничивает `attenuation` конечным `1/r_min²`, даже если источник придвинется вплотную. Направление `L` при точном совпадении всё равно не определено — поэтому совпадение исключаем отдельно, удерживая высоту.
3. На внешней границе `d = cos_outer` → `t = 0` → вклад ноль. Посередине `(cos_inner + cos_outer)/2` → `t = 0.5` → половина вклада.
4. `dot` единичных векторов — это уже косинус; переход «между косинусами» — одна строка арифметики. Перевод в углы потребовал бы `acos`, потерял бы точность и не добавил бы смысла: границы конуса мы и задали через косинусы.

:::
