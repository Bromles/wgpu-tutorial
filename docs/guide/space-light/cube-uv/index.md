# Поверхность и UV-швы

::: info Только native
Снимок [главы «Ориентация и видимость»](../depth-culling/): depth и статический кадр. Вместо треугольников — куб; камера больше не управляемая: шесть фиксированных видов по клавишам `1`–`6`.
:::

У куба восемь углов. Попробуем положить текстуру на каждую грань — и обнаружим, что восемь вершин недостаточно: **геометрическая позиция вершины — не вся вершина**.

**Эксперимент:** куб из шести явных четырёхугольников, на каждой грани размеченная текстура: маркер в текселе `(0, 0)` и разноцветные квадранты; устройство — ниже.
Клавиши `1`–`6` показывают грани по очереди; проекция — ортография, света нет.

## Почему 8 углов — это 24 записи

Возьмём угол `(0.5, 0.5, 0.5)`: он принадлежит трём граням — `+Z`, `+X` и `+Y`.
В развёртке каждой грани отведён свой кусок UV-пространства: на грани `+Z` этому углу нужен `uv = (1, 0)`, на `+X` — `(0, 0)`, на `+Y` — тоже `(0, 0)`, но «верх» развёртки смотрит в другую сторону мира.

```text
     +Y ┌───┐   Угол (0.5, 0.5, 0.5) встречается трижды:
        │ 0 │     на +Z: uv = (1, 0)
 ├───┬──┼──┬───┐  на +X: uv = (0, 0)
 │-Y │+Z│+X│-X│  на +Y: uv = (0, 0)
 ├───┴──┼──┴───┘  Позиция одна — UV три.
        │ 0 │
        └───┘  Каждая грань = отдельный
      развёртка квадрата UV
```

Один атрибут не может иметь три значения сразу: запись вершины — это **весь набор атрибутов**, `position` и `uv` путешествуют вместе.

Итого: 6 граней × 4 угла = **24 записи** и 36 индексов — по два треугольника на грань.
Углы позиций повторяются (каждый трижды), и это не расточительность, а цена независимых атрибутов: место, где UV «рвётся», называется **UV-шов**.

![Кадры cube-uv: грань +Z и грань −Z с размеченной текстурой.](/results/cube-uv-faces.png)

Слева — грань `+Z` (клавиша `1`), справа — `−Z` (клавиша `2`): экранная раскладка квадрантов одна и та же, но под чёрным маркером `uv = (0, 0)` лежат разные мировые углы — `(−0.5, 0.5, 0.5)` и `(0.5, 0.5, −0.5)`. У каждой грани собственная копия углов со своими UV — потому и 24 записи вместо восьми.

## Таблица вершин

Каждая грань записана так, как видна снаружи: первый угол — экранный верхний левый, `v` растёт вниз (тот же договор, что у текстуры [главы «Тексели и upload»](../../foundations/texture-load/)).
Позиция — четыре компонента (`w = 1`), UV — две; запись 24 байта:

```rust
#[repr(C)]
#[derive(Clone, Copy, bytemuck::Pod, bytemuck::Zeroable)]
struct Vertex {
    /// Position with w = 1: a point. Padded to four components so the record
    /// stays 4-byte aligned in both attributes.
    position: [f32; 4],
    /// Texture coordinates of this corner inside this face's copy.
    uv: [f32; 2],
}
```

```rust
impl Vertex {
    const LAYOUT: VertexBufferLayout<'static> = VertexBufferLayout {
        array_stride: 24,
        step_mode: VertexStepMode::Vertex,
        attributes: &[
            VertexAttribute { format: VertexFormat::Float32x4, offset: 0, shader_location: 0 },
            VertexAttribute { format: VertexFormat::Float32x2, offset: 16, shader_location: 1 },
        ],
    };
}
```

Сравните три записи из таблицы: одна и та же мировая точка `(−0.5, 0.5, 0.5)`, три разных UV:

```rust
// +Z face: screen right is +X, screen up is +Y.
Vertex { position: [-0.5, 0.5, 0.5, 1.0], uv: [0.0, 0.0] },
// -X face: screen right is +Z, screen up is +Y.
Vertex { position: [-0.5, 0.5, 0.5, 1.0], uv: [1.0, 0.0] },
// +Y face (top): screen right is -X, screen up is +Z.
Vertex { position: [-0.5, 0.5, 0.5, 1.0], uv: [1.0, 0.0] },
```

Почему у `−Z` «право» — это `−X`: зритель стоит на отрицательной стороне Z и смотрит в `+Z`; его правая рука указывает на `−X` (проверьте cross-произведением из [главы «Три измерения и базис»](../basis3d/)).
Индексы одинаковы для всех граней — по шесть на квадрат:

```rust
// Two triangles per face; the shared diagonal keeps the quad flat in UV.
const INDICES: [u16; 36] = [
    0, 1, 2, 2, 1, 3, // +Z
    4, 5, 6, 6, 5, 7, // -Z
    8, 9, 10, 10, 9, 11, // +X
    12, 13, 14, 14, 13, 15, // -X
    16, 17, 18, 18, 17, 19, // +Y
    20, 21, 22, 22, 21, 23, // -Y
];
```

## Размеченная текстура и маркер

Симметричная шахматка не ответит, где у грани UV-начало.
Поэтому текстура 4×4 несёт **четыре цвета по квадрантам** и один чёрный маркер: тексель `(0, 0)` — это и есть угол `uv = (0, 0)`:

```rust
pub const TEXELS: [u8; WIDTH as usize * HEIGHT as usize * 4] = [
    0, 0, 0, 255, // (0, 0): black marker of the UV origin
    255, 0, 0, 255, // (1, 0): red
    0, 255, 0, 255, // (2, 0): green
    0, 255, 0, 255, // (3, 0): green
    255, 0, 0, 255, // (0, 1): red
    255, 0, 0, 255, // (1, 1): red
    0, 255, 0, 255, // (2, 1): green
    0, 255, 0, 255, // (3, 1): green
    0, 0, 255, 255, // (0, 2): blue
    0, 0, 255, 255, // (1, 2): blue
    255, 255, 0, 255, // (2, 2): yellow
    255, 255, 0, 255, // (3, 2): yellow
    0, 0, 255, 255, // (0, 3): blue
    0, 0, 255, 255, // (1, 3): blue
    255, 255, 0, 255, // (2, 3): yellow
    255, 255, 0, 255, // (3, 3): yellow
];
```

Маркер покрывает участок `u, v < 0.25` — видимый квадратик в углу каждой грани.
Читаем без сэмплера, как в [главе «Тексели и upload»](../../foundations/texture-load/): UV масштабируется в индексы текселей, `textureLoad` берёт целый тексель:

```wgsl
@fragment
fn fs_main(input: VertexOutput) -> @location(0) vec4<f32> {
    // UV in [0, 1] scaled to texel indices; textureLoad reads whole texels
    // and the sRGB view decodes them to linear values.
    let extent = vec2<i32>(textureDimensions(FACE));
    let texel = vec2<i32>(input.uv * vec2<f32>(extent));
    return textureLoad(FACE, texel, 0);
}
```

## Шесть фиксированных видов

Камера не управляется — она последовательно занимает шесть позиций «перед гранью»: глаз на нормали в трёх метрах, up-подсказка `+Y` для боковых граней и `+Z` для верхней с нижней:

```rust
/// Six views in key order 1..6: +Z, -Z, +X, -X, +Y, -Y.
pub const FACE_VIEWS: [FaceView; 6] = [
    FaceView { eye: Vec3::new(0.0, 0.0, 3.0), up: Vec3::Y },
    FaceView { eye: Vec3::new(0.0, 0.0, -3.0), up: Vec3::Y },
    FaceView { eye: Vec3::new(3.0, 0.0, 0.0), up: Vec3::Y },
    FaceView { eye: Vec3::new(-3.0, 0.0, 0.0), up: Vec3::Y },
    FaceView { eye: Vec3::new(0.0, 3.0, 0.0), up: Vec3::Z },
    FaceView { eye: Vec3::new(0.0, -3.0, 0.0), up: Vec3::Z },
];

/// Fixed orthographic volume: -2..2 x -1.5..1.5 fits the cube with margins
/// and matches the 4:3 frame of the shell defaults.
fn ortho() -> Mat4 {
    glam::camera::rh::proj::directx::orthographic(-2.0, 2.0, -1.5, 1.5, 0.1, 10.0)
}
```

Проекция фиксирована — размер куба и вид не меняются, ортография не искажает грань перспективой.
Кадр статичен, поэтому перерисовка — ровно по событию, без цикла по часам:

```rust
let picked = match key_code {
    KeyCode::Digit1 => Some(0),
    KeyCode::Digit2 => Some(1),
    KeyCode::Digit3 => Some(2),
    KeyCode::Digit4 => Some(3),
    KeyCode::Digit5 => Some(4),
    KeyCode::Digit6 => Some(5),
    _ => None,
};
if let Some(index) = picked {
    self.face = index;
    // The frame is static: redraw exactly when a key
    // changed it, instead of looping on the clock.
    window.request_redraw();
}
```

Проверка кадра — GPU-тест: для **всех шести** видов пробуем по четыре квадранта (вдали от швов и маркера) и сам маркер. Проба задаётся в UV грани; её мировая точка восстанавливается билинейной интерполяцией по таблице вершин, ожидаемый цвет — чтением CPU-таблицы текселей.

```sh
cargo run -p cube-uv
cargo test -p foundations-verify
```

## Швы независимы

Главный вывод главы: **разрывы атрибутов не обязаны совпадать**.
UV порвался там, где грани встречаются, — но геометрия (позиции) при этом гладкая: три записи одного угла дают один и тот же `position`.
Слей мы записи до восьми «настоящих» углов — минимум у одной грани UV оказался бы чужим, и её раскладка цветов сломалась бы; верни швы — все шесть граней снова верны, изменились только UV и индексы.

Нормали, которым нужна [следующая глава](../lambert/), рвутся по-своему: не по границам граней, а по резким изломам освещённости — даже там, где позиция остаётся плоской.

## Проверьте модель

1. Сколько записей вершин понадобится кубу, если каждой грани нужны и UV, и своя нормаль? Изменится ли это число против этой главы?
2. Почему у грани `−Z` экранный «правый» угол — `(−0.5, 0.5, −0.5)`, а не `(0.5, 0.5, −0.5)`?
3. Что покажет грань, если в её четырёх записях перепутать местами `uv` первого и второго угла — `(1,0)` и `(0,0)`?
4. Маркер занимает `u, v < 0.25`. Почему пробу теста ставят в `u, v = 0.375`, а не в центр квадранта `(0.25, 0.25)`?

::: details Решения и контрольные выводы

1. Столько же — 24: нормаль, как и UV, — атрибут записи; своё значение нужно каждой грани у каждого угла. Запись становится шире (два атрибута к позиции), но не многочисленнее: швы UV и нормалей у куба совпадают.
2. Зритель грани `−Z` смотрит вдоль `+Z`, его право — `forward × up = −X`: больший X уходит влево экрана. Таблица «позиция → position/UV» фиксирует это явно.
3. Поменяются местами только UV двух верхних углов: `u` переворачивается вдоль верхнего края и остаётся собой вдоль нижнего — вместо зеркала по грани идёт скрутка (верх отражён, низ нет), маркер уезжает в верхний правый угол. Текстура — не «картинка на грани», а результат интерполяции UV, записанных в вершинах.
4. `(0.25, 0.25)` — граница четырёх текселей и край маркерного текселя `(0,0)`: интерполяция может дать любой из соседних. `(0.375, 0.375)` — центр текселя `(1,1)`, на полтакта от всех границ.

:::

Поверхность теперь несёт любой атрибут, сколько бы раз её ни «разрезали».
[Следующая глава](../lambert/) добавляет нормали и спрашивает: почему одинаково наклонённые грани светятся одинаково, а смотрятся по-разному.
