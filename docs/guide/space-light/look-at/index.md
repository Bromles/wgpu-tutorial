# Камера как система координат

::: info Только native
Контрольный кадр прежний; эксперимент главы — численный: одна мировая точка, две матрицы.
:::

Почему «камера уехала вправо» выглядит как «мир уехал влево»?
Потому что рендеринг никогда не двигает камеру: он выражает мир **в координатах камеры**.

## Обратное преобразование

У каждого перемещения с поворотом — а камера пока больше ничего и не умеет — есть обратное преобразование: `M · M⁻¹ = I`.
Если `M` переносит объект из локальных координат в мир, то `M⁻¹` возвращает мир в локальные координаты объекта.
**Матрица вида** (view) — это `M⁻¹` для камеры: `V = inverse(camera)`.

Обратимость — не формальность: у масштаба с нулевой компонентой обратной матрицы нет — пространство вдоль этой оси схлопывается (в трёх измерениях — в плоскость). Когда обратной не существует — см. сборку камеры ниже.

## Камера = положение + базис

```text
  world (Y вверх)          camera (смотрит вдоль −Z)
       ↑ up                        ↑ up
       |    backward               |
       |   ↗                 −Z ←  · eye
       |  / forward               |
       | /                        +→ right
       +──→ right

  view = inverse(camera):
  1) вычесть eye — начало координат в камере
  2) выразить в базисе камеры — оси становятся X, Y, Z
```

Соберём матрицу камеры вручную из [базиса главы «Три измерения и базис»](../basis3d/): столбцы — её оси, четвёртый столбец — положение `eye`. Полная сборка с обращением — ниже, в `manual_view`.

Оси даёт `camera_axes` из `camera.rs`: `forward = normalize(target − eye)`, `right = forward × up_hint`, `up = right × forward`, третья ось `−forward` — камера смотрит вдоль своего `−Z` (правая тройка из [главы «Три измерения и базис»](../basis3d/)).
Совпадение `eye` и `target` (нулевое направление) и параллельность `up_hint` направлению взгляда отклоняются — оба случая вырожденные.

## View: инверсия собранной камеры

Инвертируем собранную камеру и смотрим на мировые точки:

```rust
pub fn manual_view(eye: Vec3, target: Vec3, up_hint: Vec3) -> Result<glam::Mat4, String> {
    let (right, up, backward, eye) = camera_axes(eye, target, up_hint)?;
    Ok(glam::Mat4::from_cols(
        right.extend(0.0),
        up.extend(0.0),
        backward.extend(0.0),
        eye.extend(1.0),
    )
    .inverse())
}
```

Контрольные числа — камера в `(0, 0, 5)` м, смотрит в начало координат, up = +Y:

- мировой ноль получает view-координаты `(0, 0, −5)`: пять метров **вдоль направления взгляда** (−Z камеры);
- камера, сдвинутая на `+1` по X без вращения, видит тот же ноль в `(−1, 0, −5)`: мир уехал влево.

Оба — юнит-тесты, вместе с главным: `camera · view ≈ I` и совпадение `manual_view` с библиотечным `glam::camera::rh::view::look_at_mat4` с допуском `1e-5`. Конструкторы glam вводятся только после того, как мы сами посчитали то же самое.

![Кадр look-at: контрольный кадр главы — рамка T·R; собранная вручную матрица вида проверяется юнит-тестами.](/results/look-at.png)

Кадр главы — контрольная рамка с уже знакомым преобразованием `T·R`: собранная вручную матрица вида в кадр не входит, её проверяют юнит-тесты — численный эксперимент главы (в координатах камеры глаз — начало координат, а мировой ноль получает `(0, 0, −5)`).

## Проверьте модель

1. Камера повернулась влево на 90°. В какую сторону «уедет» мир во view?
2. Почему у матрицы вида нельзя «просто вычесть eye» без смены базиса?
3. Что вернёт `glam::camera::rh::view::look_at_mat4` для eye = target и почему мы отклоняем это раньше?
4. Камера в (0,0,5), target = (0,1,0): примерно куда смотрит ось −Z камеры в мире?

::: details Решения и контрольные выводы

1. Вправо: обратное вращение — поворот на −90°.
2. Вычитание eye переносит начало координат в камеру, но оси остаются мировыми; view требует и переноса, и поворота в базис камеры — это и делает обратная матрица.
3. Нулевое направление взгляда: `normalize(0)` не определён, базис не строится. Отклонение до вызова библиотеки даёт понятную причину ошибки вместо тихого NaN: glam нормализует ноль в NaN без паники и без сообщения.
4. Чуть вверх от горизонта: target `(0, 1, 0)` выше глаза, `forward = normalize((0,1,0) − (0,0,5)) ≈ (0, +0.196, −0.98)`; ось −Z камеры смотрит на target.

:::
