# Три измерения и базис

::: info Только native
Управляемый кадр — контрольный (из [главы «Матрицы и композиция»](../matrix-compose/)); новый опыт этой главы — численный, на CPU.
:::

Третье измерение существовало в наших матрицах формально: `z = 0.5`, нули по краям.
Впереди камера, которая должна смотреть в произвольном направлении: её оси придётся строить из самого направления взгляда и подсказки «верх».
Инструменты — три операции: длина, проекция и перпендикуляр.

## Local и world

У каждой модели — **локальные координаты** (local): «метка на корпусе», удобно для автора модели.
**Мировые координаты** (world) — общая система сцены; договоримся: X вправо, Y вверх, Z по правилу правой руки — **правая тройка**: X × Y = Z, большой палец X, указательный Y, средний Z.
Локальная точка — веса мировых осей: `p_world = x·X + y·Y + z·Z`; переход между системами — умножение на базис-матрицу из [главы «Матрицы и композиция»](../matrix-compose/).
Длины измеряем в условных метрах.

## Длина и нормализация

Длина — теорема Пифагора в 3D: `|v| = √(x² + y² + z²)`.
`(3, 4, 0)` имеет длину `5` — классическая тройка.
**Нормализация** делит на длину, получая единичный вектор того же направления: `(3,4,0)/5 = (0.6, 0.8, 0)`.
Нулевой вектор нормализовать нельзя: у него нет направления — glam даёт `normalize_or_zero`, наш код обязан это учитывать, а не «как-нибудь разделить на ноль».

## Dot: проекция и совпадение

Задача: сколько направления `a` лежит вдоль `b` — какая «тень» падает с `a` на направление `b`. Ответ даёт скалярное произведение, связывающее длины и угол:

```text
a · b = |a||b| cos φ
```

Для единичных векторов dot — «мера совпадения»: 1 — сонаправлены, 0 — перпендикулярны, −1 — противоположны.
Для произвольных: `a·b / |b|` — длина проекции `a` на направление `b`, та самая «тень»; в координатах единичного базиса dot с осью возвращает соответствующую компоненту.

В компонентах dot считается напрямую, без угла:

```text
a · b = a.x·b.x + a.y·b.y + a.z·b.z
```

Проверка на паре из этой главы: `(3, 4, 0) · (0, 1, 0) = 0 + 4 + 0 = 4` — проекция `(3,4,0)` на ось Y равна его `y`-компоненте. Ровно эта формула работает и в WGSL: встроенная `dot` — сумма произведений компонент.

## Cross: перпендикуляр двум векторам

Векторное произведение даёт вектор, перпендикулярный обоим аргументам:

```text
X × Y = Z        Y × X = −Z        X × X = 0
```

Порядок аргументов задаёт направление результата — правая тройка.
Параллельные аргументы вырождаются в ноль: перпендикуляра «в бесконечном числе направлений» не построить.

В компонентах (проверьте построчно на `X × Y = Z`: каждая строка — мини-формула из двух произведений):

```text
a × b = ( a.y·b.z − a.z·b.y ,   a.z·b.x − a.x·b.z ,   a.x·b.y − a.y·b.x )
```

Контроль вручную: `(1, 2, 3) × (4, 5, 6) = (2·6 − 3·5, 3·4 − 1·6, 1·5 − 2·4) = (−3, 6, −3)` — glam даст то же самое.
И то же правило в WGSL-функции `cross`.

Следствие, обещанное вместе с [той самой формулой площади](../../foundations/vertex-colors/): длина cross равна `|a||b| sin φ` — а это удвоенная площадь треугольника со сторонами `a` и `b` (основание `|b|`, высота `|a| sin φ`). Поэтому

```text
S(A, B, C) = ½ · |(B − A) × (C − A)|
```

— вот и недостающая формула площади для барицентрических весов.

## Ортонормированный базис

Задача камеры (уже следующей главы): по направлению взгляда и подсказке «верх» построить тройку осей.

```rust
let right = forward.cross(up_hint).normalize();
let up = right.cross(forward).normalize();
// The third basis axis points against forward: together with the right
// and up it forms the same right-handed triple as (X, Y, Z).
Ok((right, up, -forward))
```

`forward` — куда смотрим; `right` — перпендикуляр к `forward` и подсказке; `up` — перпендикуляр к ним обоим (уже не подсказка, а точный верх базиса).
Третья ось — `−forward`: традиция камеры, смотрящей вдоль своего `−Z`.
Все вырождения (нулевое направление, параллельная и антипараллельная подсказка, нулевая подсказка) отклоняются явно, а не маскируются:

```rust
if forward.length_squared() == 0.0 {
    return Err("forward direction must be nonzero".into());
}
// The cross product catches all three degeneracies at once: a hint
// parallel or anti-parallel to forward, and a zero hint, all produce a
// zero cross and therefore no usable second axis.
if up_hint.normalize_or_zero().cross(forward).length_squared() < 1e-10 {
    return Err("up hint is parallel to forward; basis is degenerate".into());
}
```

Проверки главы — юнит-тесты `basis.rs`: Пифагор и нормализация, знаки cross, ортонормированность построенного базиса (длины 1, попарные dot нулевые), отказ вырожденных входов.

```sh
cargo run -p basis3d
cargo test -p basis3d
```

## Проверьте модель

1. Длина `(3, 4, 0)`? Единичный вектор того же направления?
2. Что больше: dot единичных векторов под 90° или под 60°? Чему равен dot перпендикулярных?
3. Почему `Y × X = −Z`, а не `Z`? Что вернёт `X × 2X`?
4. Построение базиса с подсказкой up, параллельной forward: почему это должно быть ошибкой, а не «нулевым up»?

::: details Решения и контрольные выводы

1. `5`; `(0.6, 0.8, 0)`.
2. Под 60°: `cos 60° = 0.5`; под 90° — ровно `0`.
3. Cross антикоммутативен: смена порядка переворачивает результат. Параллельные дают нулевой вектор.
4. Тогда `forward × up_hint = 0` — перпендикуляр не определён, базис вырожден. Тихий ноль сломал бы нормализацию и повёл бы камеру в неизвестном направлении.

:::
