# Точки, направления и движение

::: info Только native
Первая глава раздела о пространстве. Продолжаем со снимка [главы «Меняем данные во времени»](../../foundations/gain-animation/): часы, upload и два draw уже есть; окно и lifecycle — из [фреймворка](../../foundations/framework-triangle/).
:::

До сих пор вершины лежали там, где их положили.
Чтобы предмет двигался, нужно различать два математических объекта, которые мы до сих пор смешивали.

**Эксперимент:** асимметричный треугольник (он не похож на себя при поворотах — это важно для контроля) ездит по экрану и вращается.
Параметры — перенос, масштаб и угол — приходят через знакомый uniform; `Space`/`R` — пауза/сброс.

## Точка и направление

**Точка** — положение в пространстве. **Направление** (смещение) — «на сколько и куда» сдвинуть.
Различие семантическое: обе записи — пара чисел `(x, y)`, но операции над ними разные.

- Перенос точки: `p' = p + t` — точка переехала.
- Перенос направления: `d' = d` — «сдвинуть на 3 метра» значит сместить точку; у направления нет положения, которое можно было бы поменять, — только длина и ориентация, и обе сохраняются.

Пара чисел без контекста не говорит, кто перед нами; контракт задаём мы.
В этой главе вершины треугольника — точки, а ось движения — направление.

Координаты пока остаются clip-подобными: X вправо, Y вверх, единица — половина высоты кадра, `z = 0.5`, `w = 1`.
Экранный Y растёт вниз, но мы договорились думать в математических координатах: переворот происходит при выводе, вершина `y = +0.3` видна сверху — так было с самого [первого треугольника](../../foundations/first-triangle/).

## Перенос и масштаб

Обе операции над точкой тривиальны, над направлением — нет:

```text
точка:      p' = p + t            перенесли
точка:      p' = p * s            растянули от начала координат
направление: d' = d * s           длиннее в s раз — имеет смысл
направление: d' = d + t           бессмыслица: t не смещение смещения
```

## Угол и радианы

Вращение задаётся углом; чтобы угол превратился в координаты вершины, измеряем его длиной дуги единичной окружности — так определены **радианы**.
Полный оборот — длина окружности `2π`; прямой угол — `π/2`.

## Единичная окружность и вращение

Точка единичной окружности под углом θ от оси X:

```text
( cos θ, sin θ )
```

При θ = 0 это `(1, 0)` — образ оси X; при θ = π/2 — `(0, 1)` — образ оси Y.
Значит, поворот на θ переводит базисные направления так:

```text
X → (cos θ, sin θ)         Y → (−sin θ, cos θ)
```

(Второе — точка окружности под углом θ + π/2: `cos(θ+π/2) = −sin θ`, `sin(θ+π/2) = cos θ`.)

Произвольная точка — сумма компонентов по базису: `p = x·X + y·Y`; поворот каждого слагаемого даёт

```text
x' = x·cos θ − y·sin θ
y' = x·sin θ + y·cos θ
```

Это и есть **вращение**. Направление вращается той же формулой — у него те же компоненты, только смысл другой.

## Снимок

Шейдер применяет цепочку «масштаб → поворот → перенос» к каждой вершине:

```wgsl
struct Params {
    translate: vec2<f32>,
    scale_angle: vec2<f32>,
};

@group(0) @binding(0) var<uniform> params: Params;

@vertex
fn vs_main(input: VertexInput) -> VertexOutput {
    // Scale first, then rotate the scaled local offset, then place the
    // resulting point at the translation. cos/sin of the angle give the
    // images of the unit X and Y directions.
    let local = input.position.xy * params.scale_angle.x;
    let angle = params.scale_angle.y;
    let c = cos(angle);
    let s = sin(angle);
    let rotated = vec2<f32>(c * local.x - s * local.y, s * local.x + c * local.y);
    var output: VertexOutput;
    output.position = vec4<f32>(rotated + params.translate, 0.5, 1.0);
    output.color = input.color.rgb;
    return output;
}
```

`sin`/`cos` — встроенные функции WGSL; формулы выше — их обоснование, а не «магия библиотеки».
Движение задаёт CPU: пинг-понг вдоль X со скоростью `0.2` единицы/с и вращение `0.5` рад/с:

```rust
// Triangular wave: x starts at +TRAVEL, folds back at the edges.
let distance = (SPEED * elapsed) % (4.0 * TRAVEL);
let x = (distance - 2.0 * TRAVEL).abs() - TRAVEL;
```

Пройденный путь сворачивается в позицию: расстояние `SPEED·t` берётся по модулю **полного** периода `4·TRAVEL` (амплитуда поездки `TRAVEL = 0.6`), а модуль разности со серединой диапазона отражает его вниз и вверх.
Проверьте руками: при `distance = 0` → `x = +0.6`; при `2·TRAVEL` (через `2·TRAVEL/SPEED = 6` с) → `x = −0.6`; при `4·TRAVEL` снова `+0.6` — и в обеих точках разворота положение непрерывно (скачка, как у простого остатка, нет — это и проверяют юнит-тесты).
Простой `%` без отражения дал бы пилообразный скачок с `−0.6` на `+0.6` один раз за период.

`Vec2` здесь — тип из крейта glam для пары `f32`; пока это просто удобный контейнер двух компонент, его математический смысл раскроется в следующих главах.

Автоматическая проверка гоняет три набора параметров (тождественный, поворот π/2 с переносом, масштаб с произвольным углом) и сверяет регулярную сетку строго внутренних проб с барицентрической моделью в новых вершинах — та же механика, что в [«Интерполяции»](../../foundations/vertex-colors/).

![Кадры triangle-motion: асимметричный треугольник в двух позах.](/results/triangle-motion-poses.png)

Одна модель — две позы: параметры переноса, масштаба и угла приходят через uniform, шейдер применяет их цепочкой «масштаб → поворот → перенос». Асимметричный треугольник не похож на себя при поворотах — любое изменение параметров видно сразу.

```sh
cargo run -p triangle-motion
cargo test -p triangle-motion
```

## Проверьте модель

1. Поверните `(0.25, 0)` на `π/2`. Куда попала точка? Прибавьте `(0.1, 0.2)` — что получилось?
2. Чем ответ предыдущего пункта отличался бы для направления `(0.25, 0)`?
3. Почему для стенда выбран асимметричный треугольник?
4. Масштаб `0.5` и поворот применяются в записанном порядке. Что изменится, если применить поворот к уже перенесённой точке?

::: details Решения и контрольные выводы

1. `x' = 0.25·cos(π/2) = 0`, `y' = 0.25·sin(π/2) = 0.25` → `(0, 0.25)`; после переноса — `(0.1, 0.45)`.
2. Поворот — тот же, а перенос направление не меняет: результат остался бы `(0, 0.25)`.
3. Равносторонний или равнобедренный треугольник при некоторых поворотах выглядит как исходный — потеря контроля. Асимметричный выдаёт любое изменение.
4. Получилась бы другая траектория: вращение вокруг начала координат после переноса — это орбита, а не собственное вращение. Порядок операций — тема [следующей главы](../matrix-compose/).

:::

Каждое преобразование — своя пара формул, и их приходится применять в строго задуманном порядке.
