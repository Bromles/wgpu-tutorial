# Преобразование нормалей

::: info Только native
Новая сцена: одна грань из двух касательных; свет `L = normalize(1, 0, 1)`, камера на диагонали `(5/√2, −5/√2, 0)` смотрит вдоль нормали грани.
Плоскость (t, b) при этом видна целиком, и любой излом освещения на ней виден сразу; с точки +Z, вдоль b, грань была бы видна с ребра — тоньше некуда.
Клавиша `X` меняет масштаб model по оси X.
:::

До сих пор модель была тождественной: нормали вершины попадали в мир без изменений.
Первое же нетождественное преобразование ломает наивную передачу — и не из-за точности, а из-за математики.

**Эксперимент:** одна грань построена из касательных `t=(1,1,0)` и `b=(0,0,1)`.
Клавиша `X` переключает масштаб model по X: `1 ↔ 2`; камера и свет при этом неподвижны.
`albedo = 0.5`, `ambient = 0.1`, `intensity = 0.6`; culling выключен, а depth-буфер из [главы «Ориентация и видимость»](../depth-culling/) убран — перекрывающихся поверхностей здесь нет, и смешивание граней не отвлекает от сравнения освещённости.

## Грань из двух касательных

Грань [главы «Нормали и первый свет»](../lambert/) зададим явно формулой, а не списком вершин: четыре угла — все комбинации `(±t ±b)·0.5`, квадрат в плоскости `(t, b)` с центром в нуле; нормаль — их cross-произведение:

```rust
const TANGENT_T: Vec3 = Vec3::new(1.0, 1.0, 0.0);
const TANGENT_B: Vec3 = Vec3::new(0.0, 0.0, 1.0);
```

```text
n = t × b = (1, −1, 0)        единичная: (0.7071, −0.7071, 0)
углы: (+t+b)/2, (+t−b)/2, (−t−b)/2, (−t+b)/2
```

Все четыре вершины несут одну и ту же нормаль — грань плоская, ориентация общая.

## Что ломается при масштабе

Масштаб `X×2` — матрица `M = diag(2, 1, 1)`.
Касательное направление растягивается вместе с гранью: `M·t = (2, 1, 0)`.
А теперь то же преобразование для нормали:

```text
M·n = (2, −1, 0)
(M·n)·(M·t) = 2·2 + (−1)·1 = 3        было n·t = 0
```

Скалярное произведение с преобразованной касательной равно **трём**: нормаль больше не перпендикулярна поверхности.
Заметьте: проблема настоящая, а не косметическая — грань при неравномерном масштабе действительно наклоняется в мире, и её нормаль *должна* измениться.
Вопрос в том, какой матрицей.

## Перенос членов скалярного произведения

Скалярное произведение — это умножение строк на столбцы: `a·b = aᵀb`.
**Транспонирование** меняет строки и столбцы местами: `(Aᵀ)ᵢⱼ = Aⱼᵢ`, и тогда члены произведения можно переносить:

```text
(N·n)·(M·t) = (N·n)ᵀ·(M·t) = nᵀ·Nᵀ·M·t
```

Требование: перпендикулярность должна сохраняться — `(N·n)·(M·t) = n·t` для любых `n ⊥ t`.
Подставим: `nᵀ·Nᵀ·M·t = nᵀ·t` для всех пар, и это возможно только при

```text
Nᵀ·M = I        N = (M⁻¹)ᵀ
```

**Нормальную матрицу** даёт обратная транспонированная линейная часть model.
Проверка на наших числах: `M⁻¹ = diag(0.5, 1, 1)`, поэтому `N·n = (0.5, −1, 0)`, и

```text
(N·n)·(M·t) = 0.5·2 + (−1)·1 = 0
```

перпендикулярность восстановлена.
(Для диагонального масштаба `(M⁻¹)ᵀ` совпадает с `M⁻¹`; для чистого вращения — с самим `M`, так что наивная формула случайно права. Разойтись с `M·n` формула может на сдвиге (shear) и на комбинации вращения с неравномерным масштабом — но формула одна на все случаи.)

Нормализация неверной нормали ошибку не лечит: `(2,−1,0)/√5` и правильное `(0.5,−1,0)/√1.25` — просто разные направления.

## Только линейная часть

Перенос из model не должен попадать в нормаль: у направления `w = 0`, и столбец переноса умножается на ноль (договор [главы «Матрицы и композиция»](../matrix-compose/)).
Поэтому берём линейную 3×3 часть, инвертируем и транспонируем — на CPU это три вызова glam после вывода выше:

```rust
    pub fn from_scale(scale: Vec3) -> Result<Self, String> {
        if scale.cmpeq(Vec3::ZERO).any() {
            return Err(format!(
                "scale {scale} has a zero component; the normal matrix is undefined"
            ));
        }
        let model = Mat4::from_scale(scale);
        // Linear 3x3 part only: translation never applies to a direction.
        let normal_matrix = Mat4::from_mat3(Mat3::from_mat4(model).inverse().transpose());
        Ok(Self {
            model,
            normal_matrix,
        })
    }
```

Масштаб с нулевой компонентой отклоняется явной ошибкой: у схлопнувшейся оси нет обратной матрицы, а подстановка identity молча прятала бы вырождение.

## Снимок

Uniform объекта — пара матриц по знакомому контракту [«Смешанные поля»](../../foundations/uniform-params/): два `mat4x4`, 128 байт:

```wgsl
struct ModelParams {
    model: mat4x4<f32>,
    normal_matrix: mat4x4<f32>,
};

@group(0) @binding(0) var<uniform> view_proj: mat4x4<f32>;
@group(0) @binding(1) var<uniform> model_params: ModelParams;
```

Каждая вершина проходит двумя дорогами: позиция — через model, нормаль — через normal matrix с `w = 0`:

```wgsl
    output.position = view_proj * model_params.model * input.position;
    // Normals: a direction (w = 0, no translation) through the
    // inverse-transpose, which keeps it perpendicular to the transformed
    // tangents.
    output.world_normal = (model_params.normal_matrix * vec4<f32>(input.normal.xyz, 0.0)).xyz;
```

Фрагментный шейдер — ламберт из [главы «Нормали и первый свет»](../lambert/), с ренормализацией после интерполяции (normal matrix меняет длину):

```wgsl
    let n = normalize(input.world_normal);
    let d = max(dot(n, LIGHT_DIR), 0.0);
    let color = vec3<f32>(ALBEDO * (AMBIENT + INTENSITY * d));
```

Проверка гоняет оба масштаба и сверяет центр грани с CPU-моделью (`(M⁻¹)ᵀ·n`, посчитанной glam): код `124` при `X×1` и `106` при `X×2` — грань честно повернулась к свету.
Наивные `M·n` дали бы третью величину — `134`.

![Кадры normal-matrix: грань при масштабе X×1 и X×2.](/results/normal-matrix-scale.png)

Слева `X×1`, справа `X×2` — сравните центры: код меняется с `124` на `106`, потому что растянутая грань честно меняет наклон к свету. Наивное `M·n` дало бы `134`: перпендикуляр, «растянутый» вместе с геометрией, перпендикуляром быть перестаёт.

```sh

cargo test -p verify
```

## Проверьте модель

1. Для `M = diag(2, 1, 1)` посчитайте `M·n`, `(M⁻¹)ᵀ·n` для `n = (1, −1, 0)` и проверьте оба через скалярное произведение с `M·t = (2, 1, 0)`.
2. Почему столбец переноса model не должен попадать в преобразование нормали, даже если мы используем полную `Mat4`?
3. Что произойдёт при равномерном масштабе 2: совпадут ли `M·n` и `(M⁻¹)ᵀ·n` после нормализации?
4. Почему масштаб с нулевой компонентой мы отклоняем ошибкой, а не заменяем identity?

::: details Решения и контрольные выводы

1. `M·n = (2, −1, 0)`, произведение с `(2, 1, 0)` равно `3 ≠ 0`. `(M⁻¹)ᵀ·n = (0.5, −1, 0)`, произведение `0.5·2 − 1 = 0` — перпендикулярность на месте.
2. Нормаль — направление с `w = 0`: столбец переноса умножается на ноль. Матрица `Mat4` с нулевой трансляцией даёт те же три компоненты, но явно отделённая линейная часть документирует, что перенос не участвует.
3. Совпадут: `M = 2I`, `M⁻¹ = 0.5I`, `(M⁻¹)ᵀ = 0.5I`; оба вектора `(2,−2,0)` и `(0.5,−0.5,0)` после нормализации равны. Неравномерный масштаб — минимальный случай, где пути расходятся.
4. Нулевая ось схлопывает грань в линию: обратной матрицы нет, нормали не существует. Молчаливый identity выдал бы неправильное изображение без предупреждения — ошибка честнее.

:::

Грань теперь честно освещена при любом масштабе — но сама она пока матовая.
