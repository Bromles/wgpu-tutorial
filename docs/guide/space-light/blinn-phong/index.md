# Материал и блик

::: info Только native
Снимок [главы «Преобразование нормалей»](../normal-matrix/): наклонная грань заменена плоскостью XY, `model = identity`; клавиши `[`/`]` и `C`.
:::

Две одинаково ориентированные матовые поверхности при одном свете неотличимы.
Но добавьте блик — и они засветятся по-разному, стоит наблюдателю сдвинуться.
Значит, в формуле появился новый участник: **глаз**.

**Эксперимент:** плоскость `z = 0` с нормалью `+Z`, направленный свет `L = +Z`, камера `(0, 0, 3)` с fov 60°.
Направленный свет и диффузная часть — из [главы «Нормали и первый свет»](../lambert/); `albedo = 0.5`, `ambient = 0.1`, `intensity = 0.6`, `specular = 0.7`.
Клавиши: `[` и `]` меняют показатель блика (1…128, степени двойки), `C` — положение камеры: `(0,0,3)`, `(1.5,0,3)`, `(0,1.5,3)`.

## V: направление на глаз

У каждого фрагмента есть мировое положение `P` — то самое, что мы возили через матрицы [главы «Преобразование нормалей»](../normal-matrix/).
Теперь оно нужно само по себе: передаём его как varying и строим направление на глаз

```text
V = normalize(eye − P)
```

Даже на плоскости с неподвижной камерой `V` меняется от точки к точке: глаз — точка, а не направление.
Диффузному члену это безразлично (`N·L` от `P` не зависит), а блик — следствие именно `V`.

## Половинный вектор H

Зеркальный блик виден там, где поверхность отражает свет в глаз: по закону зеркального отражения луч отскакивает под тем же углом, под каким упал.
Blinn–Phong проверяет это, сравнивая нормаль с **половинным вектором** между направлениями на источник и на глаз:

```text
H = normalize(L + V)        блик: max(N·H, 0) в степени shininess
```

Если `N` смотрит ровно между `L` и `V`, блик максимален: `N·H = 1`.
В центре нашей плоскости при камере `(0, 0, 3)`: `P = (0, 0, 0)`, `V = (0, 0, 1) = L`, значит `H = +Z = N` — пик блика точно в центре кадра.
Сдвиньте камеру клавишей `C` — `V` в центре наклонится, `H` уйдёт от `N`, и пик сместится вместе с глазом.

## Показатель: узкий или широкий

`N·H` само по себе — мягкий купол.
Степень заостряет его:

```text
0.8⁸  ≈ 0.168        0.8³² ≈ 0.000792
```

при `N·H = 0.8` показатель 8 оставляет заметный отсвет, 32 — почти ноль: блик сужается, не сдвигая вершины.
Вершина (`N·H = 1`) даёт `pow(1, shininess) = 1` при любом показателе — яркость пика он не меняет: её задаёт `specular`.

## Материал отдельно от источника

`albedo`, цвет блика `specular` и `shininess` — свойства *поверхности*; `eye` и `L` — свойства *сцены*.
Данные это отражают: одна uniform-структура с вложенной `Material`:

```rust
#[derive(ShaderType, Debug, Clone, Copy, PartialEq)]
pub struct Material {
    pub albedo: Vec3,
    pub specular: Vec3,
    pub shininess: f32,
}
```

encase выравнивает каждый `vec3` на 16 байт, а размер структуры округляет вверх до её выравнивания — итого **128 байт**; точные смещения полей — в комментарии ниже. Хвост каждого `vec3` (4 байта) и хвост `Material` — padding той же природы, что и в [«Смешанные поля»](../../foundations/uniform-params/): это округление действует во всех адресных пространствах, не только в uniform. WGSL-зеркало повторяет раскладку поле в поле (юнит-тест сверяет байты буквально):

```wgsl
struct Material {
    albedo: vec3<f32>,
    specular: vec3<f32>,
    shininess: f32,
};

// Matches the encase layout: the matrix first, then each vec3 aligned to
// 16 bytes (eye 64, light_dir 80), the nested Material at 96; 128 bytes in
// total = roundUp(16, 96 + 32).
struct Params {
    view_proj: mat4x4<f32>,
    eye: vec3<f32>,
    light_dir: vec3<f32>,
    material: Material,
};
```

Фрагментный шейдер собирает оба члена. Поверхность — **односторонняя**: прямой свет (диффуз и блик) существует, только когда и свет, и глаз находятся по одну сторону с нормалью.
`max(N·L, 0)` гасит диффуз обратной стороны, но блик потребовал собственной оговорки: при `N·L ≤ 0` (источник за плоскостью) `N·H` всё ещё может быть положительным — половинный вектор способен «смотреть» на нормаль, даже когда свет светит в затылок.
Поэтому specular вычисляется только при `N·L > 0` **и** `N·V > 0`, а вырожденный случай `L + V ≈ 0` (глядим точно против света) не нормализуется — блик остаётся нулём:

```wgsl
    let n = normalize(input.world_normal);
    let l = params.light_dir;
    // V points from the fragment toward the eye: it varies across the
    // plane even though N and L never move.
    let v = normalize(params.eye - input.world_position);
    let diffuse = max(dot(n, l), 0.0);
    var spec_factor = 0.0;
    // One-sided: no specular unless the light and the eye face the normal.
    if (diffuse > 0.0 && dot(n, v) > 0.0) {
        let l_plus_v = l + v;
        // V exactly against L leaves no half vector; no highlight.
        if (length(l_plus_v) > 0.0) {
            let h = normalize(l_plus_v);
            spec_factor = pow(max(dot(n, h), 0.0), params.material.shininess);
        }
    }
    let color = params.material.albedo * (AMBIENT + INTENSITY * diffuse)
        + params.material.specular * (INTENSITY * spec_factor);
```

Проверка сверяет центр и окраины кадра с CPU-моделью: в центре `0.5·(0.1+0.6) + 0.7·0.6 = 0.77` линейных — код `227`; со второго пресета камеры центр падает до `192`: блик уехал вместе с глазом.

![Кадры blinn-phong: диффузный член, только блик и полная сумма.](/results/blinn-phong-terms.png)

Слева только диффузный член (`specular = 0`) — матовый купол `N·L`; в центре только блик (`albedo = 0`); справа их сумма. Блик сидит в центре кадра, где `H = N`, и смещается вместе с глазом — клавишей `C`.

```sh
cargo run -p blinn-phong
cargo test -p blinn-phong
cargo test -p blinn-phong
```

## Проверьте модель

1. Камера ушла в `(1.5, 0, 3)`, свет по-прежнему `+Z`. Больше или меньше `N·H` в центре кадра, чем раньше, и куда сместится пик блика?
2. Показатель меняется с 8 на 128. Изменится ли яркость в точке, где `N·H = 1`? А её положение?
3. Плоскость перевернули: `N = −Z`, свет и камера те же. Что покажет формула? А если вместо этого оставить `N = +Z` и завести источник за плоскость (`L = −Z`)?
4. Почему `V` нельзя посчитать один раз на кадр, как `L`?

::: details Решения и контрольные выводы

1. Меньше: `V = normalize(1.5, 0, 3)` уже не совпадает с `L`, `H = normalize(L+V)` отклоняется от `+Z`, и `N·H ≈ 0.973` вместо 1. Пик уходит в точку плоскости под глазом — `(1.5, 0, 0)`, где `V` снова вертикален; на экране (камера по-прежнему смотрит в начало координат) это правее центра, на той же высоте.
2. Не изменится: `pow(1, s) = 1` при любом `s`. Показатель управляет только шириной, вершина и её яркость — свойства геометрии и `specular`.
3. Перевёрнутая плоскость: `dot(N, L) = −1 < 0` — диффус гаснет, и блик тоже: `N·L ≤ 0` запрещает прямой свет целиком, остаётся `albedo·ambient = 0.05`.
   Источник за плоскостью (`L = −Z`, `N = +Z`): ловушка — `N·V` остаётся положительным (камера спереди), и `N·H` тоже может быть положительным, так что «голая» формула блика дала бы свет. Но односторонняя модель гасит и этот случай: `N·L ≤ 0` — света нет, остаётся тот же ambient `0.05`. Обратная сторона в этой модели не светится и не бликует ни при каком положении глаза.
4. `L` — направление у направленного источника, одно на всю сцену. `V = normalize(eye − P)` зависит от `P` каждого фрагмента: на плоскости он свой в каждой точке.

:::

Источник пока один и «без адреса»: направленный свет — это только направление.
