### Правила ID и файлов

- Ссылка на целый ID (например, 19) означает завершение всех его частей, если явно не названа 19a. Внутри разделённого ID части идут по порядку. Разбиения ответвлений имеют точные входы в паспортах: например, bloom не требует всех алгоритмов B5.
- Для новых материалов при реализации использовать парные каталоги `docs/guide/<section>/<slug>/index.md` и `code/guide/<section>/<slug>/`; `slug` — смысловое имя строчными буквами, для исполняемых контрольных точек оно же имя Cargo-пакета. Числовые ID остаются внутренними идентификаторами планирования и порядком в оглавлении, а не адресом страницы или пакета. Разделы: `foundations` (01–14), `space-light` (15–28), `frame` (29–34), `branches` (B1–B8), `advanced-lighting` (B9). Реализованные соответствия: 01 → `image-data`, 02 → `cpu-gpu-queue`, 03a → `first-frame`, 03b → `surface-lifecycle`, 04 → `first-triangle`, 05 → `shell-triangle` (крейт `shell`), 06 → `vertex-colors`, 07a → `vertex-fetch`, 07b → `indexed-geometry`, 08a → `uniform-tint`, 08b → `uniform-params`, 09 → `gain-animation`, 10 → `vertex-pulling`, 11 → `draw-immediates`, 12 → `srgb-mixing`, 13a → `texture-load`, 13b → `texture-sampling`, 14 → `mipmap-minification`; 15 → `triangle-motion`, 16 → `matrix-compose`, 17 → `basis3d`, 18 → `look-at`, 19a → `ortho-perspective`, 19b → `clip-viewport`, 20 → `depth-culling`, 21 → `camera-fly`, 22 → `cube-uv`, 23 → `lambert`, 24 → `normal-matrix`, 25 → `blinn-phong`, 26a → `light-point`, 26b → `light-list`, 27a → `blend-over`, 27b → `blend-order`, 28 → `scene-objects`; 29 → `compute-basics`, 30a → `render-to-texture`, 30b → `image-pipeline`, 31a → `shadow-mapping`, 31b → `shadow-pcf`, 32 → `msaa-resolve`, 33 → `hdr-output`, 34 → `full-frame`. Эталонные кадры проверяет крейт `foundations-verify`.
- У каждой исполняемой контрольной точки будет законченный пакет; `cargo run -p <package>` и карта файлов указываются в статье после выбора имён пакетов. Для теоретической страницы достаточно явной ссылки на неизменный предыдущий пример, не копии ради номера.
- Имена `sample.rs`, `geometry.rs`, `params.rs` в паспортах обозначают ответственность, а не обязательное число модулей. Короткий код оставлять рядом; выносить только когда это помогает чтению.
- Указываем исходный снимок и переносимые модули явно. Возврат к простому стенду не означает перенос всех накопленных эффектов: например, первый compute начинается от данных 11, а не от освещённой сцены 28.

## Единый формат паспорта

Пять пунктов: **вопрос/вход → стенд/переход → объяснение/схема → код/границы → проверка**. Новые понятия следуют порядку карты; математика, WGSL-интерфейс и контракт ресурса объясняются до применения. Численные ожидания основного маршрута реализованы как реальные проверки (тесты и эталонные кадры в `foundations-verify`); для нереализованных ответвлений они остаются проектом.

- До 21 управление сравнением выполняется локальными константами или уже объяснёнными событиями winit. Никакого необъяснённого GUI, font renderer или input controller.
- Подписи и стрелки допустимы в иллюстрации без реализации их отрисовки в приложении. Если ориентацию нужно проверить в самой программе, используем известные пиксельные маркеры, а не скрытые шрифты/ассеты.
- При A/B фиксируем сцену, камеру, время, разрешение, свет и одинаковые входные данные. Численная проверка относится к указанному пространству/формату, а не к субъективной яркости монитора.
- До B1 численные GPU-значения проверяем расчётом/кодом и известной визуализацией; не вводим readback незаметно. B1 объясняет completion/map/readback до точных сравнений массивов с CPU в поздних ветках.
- Любые допуски обусловлены форматом, диапазоном значений и округлением. На этапе реализации проверить их достаточность; нельзя объявлять случайно выбранный порог универсальным для GPU и сцен.

## Замороженная оболочка

В 03 локальный bootstrap уже объясняет параметры device/features/limits, окно, raw winit-события и resize. В 05 извлекаем **одну минимальную общую библиотеку оболочки**, не копируем растущий framework во все главы.

- Оболочка владеет window/surface lifecycle, acquire/submit/present и передаёт примеру доступ к уже известным device/queue/frame/encoder.
- Параметры инициализации и требования к device задаются локальным примером через объяснённую в 03 границу конфигурации. Оболочка не знает слов «immediates», «камера», «тени» или «PBR» и не запрашивает все доступные features.
- Уже известные события окна/устройства и resize передаются локальному коду; window доступен для знакомых операций. Это forwarding, а не общая модель ввода. Накопление delta, время, движение и focus-policy контроллера вводятся и остаются в соответствующих снимках.
- Поэтому 11 может запросить IMMEDIATES, 20 пересоздать depth texture, а 21 реализовать камеру без добавления новых обязанностей оболочке. Конкретную сигнатуру API выводим при извлечении существующего кода, не проектируем здесь систему callbacks на все будущие случаи.
- При неподдерживаемой обязательной возможности пример сообщает, чего не хватает. Уже известный альтернативный путь можно запустить отдельно; не строим скрытую систему автоматических fallback во всех главах.
- После 05 общий функциональный объём заморожен. Камера, геометрия, ресурсы сцены и поздний render graph локальны снимкам и доступны только в уже объяснённой версии.

## Границы ответвлений

- B3 демонстрирует общий принцип удаления избыточности на простом знаке из треугольников; это не воспроизведение рендерера игры. Способ доступа и числовое сжатие меняются отдельно.
- B5 разделён на соседние чтения, общую память, атомарный отбор, reduction и scan. Они не нужны обязательным пакетом для каждого эффекта: B6a использует фильтр, B6b — независимые слоты.
- B7a демонстрирует frustum culling и indirect drawing без occlusion culling и универсального batching. B7b строит локальный граф знакомого bloom-кадра; отдельное хранение логических версий исключает скрытую проблему перезаписи, allocator/aliasing вне объёма.
- B8 отделяет загрузку сцены от модели отражения. Угловая мера и нормировка BRDF объясняются до direct PBR, затем идут интегрирование окружения и reference specular IBL. Skinning, realtime prefilter/split-sum и универсальный asset pipeline не входят в эти паспорта.
- B9 получает **реализуемые учебные варианты**: базовый deferred; сравнение/forward-прозрачность; CPU tiled; GPU tiled; clustered как расширение тех же списков. Общие forward/deferred lighting и light-list interface используются повторно, четыре отдельных рендерера не строим. Deferred MSAA обсуждаем, но не реализуем в базовом сравнении; depth reconstruction оставляем явно необязательным упражнением.
